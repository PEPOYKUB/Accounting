# เช็กลิสต์ก่อนใช้งานจริง

เอกสารนี้สำหรับผู้ดูแลระบบ ทำให้ครบก่อนเริ่มบันทึกข้อมูลบัญชีจริงของกิจการ

---

## ส่วนที่ 1 — ติดตั้งระบบ

### 1.1 เปิดระบบครั้งแรก

```bash
docker compose up -d --build
```

เปิด **http://localhost:3100** ระบบจะพาไปหน้าติดตั้งอัตโนมัติ กรอก

- ชื่อกิจการ · เลขประจำตัวผู้เสียภาษี 13 หลัก · รหัสสาขา · ที่อยู่ตามที่จดทะเบียน
- **วันเริ่มต้นปีบัญชี** — ระบบสร้างงวดบัญชี 12 งวดให้อัตโนมัติ รอบบัญชีไม่ตรงปีปฏิทินก็ได้
- ชื่อผู้ใช้ ชื่อ-นามสกุล และรหัสผ่านของผู้ดูแลระบบคนแรก (ได้บทบาทผู้จัดการบัญชี)

> **จดรหัสผ่านไว้ให้ดี** ระบบยังไม่มีฟังก์ชันลืมรหัสผ่าน · ถ้าลืมต้องตั้งใหม่ผ่านฐานข้อมูลโดยตรง

### 1.2 เปลี่ยนรหัสผ่านฐานข้อมูล

แก้ `docker-compose.yml` สองจุดให้ตรงกัน แล้วสร้างฐานข้อมูลใหม่ก่อนเริ่มกรอกข้อมูลจริง

```yaml
POSTGRES_PASSWORD: <รหัสผ่านใหม่>
DATABASE_URL: postgres://postgres:<รหัสผ่านใหม่>@db:5432/accounting
```

### 1.3 ให้บริการผ่าน HTTPS

จำเป็นถ้าเข้าใช้งานจากนอกเครือข่ายภายใน เพราะรหัสผ่านและคุกกี้เซสชันจะวิ่งเป็นข้อความเปล่าบน http

ระบบตรวจโปรโตคอลจาก `x-forwarded-proto` ให้เอง เมื่ออยู่หลัง reverse proxy ที่เป็น HTTPS
คุกกี้จะตั้ง `Secure` อัตโนมัติ ไม่ต้องแก้อะไรเพิ่ม

ถ้า proxy เปลี่ยนค่า Host ให้ใส่โดเมนใน `docker-compose.yml` ตรง `args: ALLOWED_ORIGINS`
แล้วสั่ง `docker compose up -d --build web`

### 1.4 วางแผนสำรองข้อมูล

พ.ร.บ.การบัญชี 2543 กำหนดให้เก็บบัญชีและเอกสารประกอบไว้ **5 ปี**

สำรองฐานข้อมูล

```bash
docker compose exec -T db pg_dump -U postgres -Fc accounting > backup_2569-08-12.dump
```

กู้คืน

```bash
docker compose exec -T db pg_restore -U postgres -d accounting --clean backup_2569-08-12.dump
```

ตั้งเป็นงานประจำวัน และเก็บสำเนาไว้นอกเครื่องอย่างน้อยหนึ่งชุด

## ส่วนที่ 2 — ตั้งค่าให้พร้อมบันทึกเอกสาร

แดชบอร์ดจะแสดงเช็กลิสต์นี้ให้จนกว่าจะครบ

| ลำดับ | สิ่งที่ต้องทำ | เมนู |
|---|---|---|
| 1 | ตรวจข้อมูลกิจการให้ถูกต้อง | ตั้งค่า → ตั้งค่ากิจการ |
| 2 | ตรวจว่ามีงวดบัญชีที่เปิดอยู่ | บัญชี → งวดบัญชี |
| 3 | เพิ่มบัญชีธนาคารที่ใช้จริง | ตั้งค่า → บัญชีธนาคาร |
| 4 | เพิ่มลูกค้า | ตั้งค่า → ลูกค้าและผู้ขาย |
| 5 | เพิ่มผู้ขาย | ตั้งค่า → ลูกค้าและผู้ขาย |

### 2.1 ปรับผังบัญชีให้ตรงกับกิจการ

**เมนู:** บัญชี → ผังบัญชี

ผังบัญชีเริ่มต้น 79 บัญชีออกแบบสำหรับธุรกิจบริการทั่วไป ควรให้ผู้ทำบัญชีตรวจและปรับ

- เพิ่มบัญชีรายได้และค่าใช้จ่ายที่กิจการใช้จริง
- ปิดใช้งานบัญชีที่ไม่ได้ใช้ (ปิดได้ ลบไม่ได้ เพื่อรักษาการตรวจสอบย้อนหลัง)
- **ห้ามเปลี่ยนประเภทบัญชีที่มีรายการแล้ว** ระบบจะปฏิเสธเอง เพราะทำให้งบย้อนหลังเพี้ยน

> ให้ผู้ทำบัญชีหรือผู้สอบบัญชีตรวจ [posting-rules.md](posting-rules.md) ด้วย
> โดยเฉพาะอัตราภาษีหัก ณ ที่จ่ายรายประเภทเงินได้ และนโยบายค่าเสื่อมราคา

### 2.2 เพิ่มผู้ใช้และกำหนดบทบาท

**เมนู:** ตั้งค่า → ผู้ใช้งาน

| บทบาท | เหมาะกับใคร |
|---|---|
| ผู้จัดการบัญชี | หัวหน้าฝ่ายบัญชี — ปิดงวด อนุมัติ จัดการผู้ใช้ |
| นักบัญชีอาวุโส | ลงบัญชีมือ กลับรายการ ปรับปรุงสิ้นงวด |
| นักบัญชี AR/AP | ออกเอกสารและบันทึกรับ-จ่ายเงินประจำวัน |
| ผู้บริหาร | เจ้าของกิจการที่ดูรายงานอย่างเดียว |
| ผู้สอบบัญชี | ผู้สอบบัญชีภายนอก ดูได้รวมถึงบันทึกการแก้ไข |

### 2.3 เปิดกฎแยกผู้บันทึกกับผู้อนุมัติ

**เมนู:** ตั้งค่า → ตั้งค่ากิจการ

ตอนติดตั้งระบบปิดกฎนี้ไว้ เพราะมีผู้ใช้คนเดียวจะบันทึกอะไรไม่ได้เลย

**เมื่อมีผู้มีสิทธิ์อนุมัติตั้งแต่ 2 คนขึ้นไปแล้ว ควรเปิด** เป็นหลักการควบคุมภายในที่ผู้สอบบัญชีคาดหวัง
ถ้าทีมมีคนเดียวจริง ๆ ปิดไว้ได้ แต่ควรบันทึกเหตุผลไว้

## ส่วนที่ 3 — นำยอดยกมาเข้าระบบ

ทำเฉพาะกรณีเริ่มใช้ระบบทั้งที่กิจการดำเนินงานมาแล้ว

### 3.1 เตรียมข้อมูล

จากงบทดลอง ณ วันก่อนเริ่มใช้ระบบ

- ยอดคงเหลือทุกบัญชี
- **รายตัวลูกหนี้ที่ค้างชำระ** พร้อมเลขที่ใบแจ้งหนี้เดิมและวันครบกำหนด
- **รายตัวเจ้าหนี้ที่ค้างจ่าย**
- ทะเบียนสินทรัพย์พร้อมค่าเสื่อมราคาสะสม

### 3.2 บันทึกยอดยกมา

**เมนู:** บัญชี → ลงบัญชีมือ → เลือกประเภทรายการ **"ยอดยกมา"**

```
Dr  สินทรัพย์ทุกบัญชี              ยอดคงเหลือ ณ วันเริ่มระบบ
    Cr  หนี้สินและส่วนของผู้ถือหุ้นทุกบัญชี   ยอดคงเหลือ ณ วันเริ่มระบบ
```

ใช้วันที่เป็นวันสุดท้ายก่อนเริ่มใช้ระบบ เช่น เริ่มใช้ 1 ม.ค. ให้ลงวันที่ 31 ธ.ค. ปีก่อน

> **ข้อจำกัดที่ต้องรู้** ยอดลูกหนี้และเจ้าหนี้ยกมาที่บันทึกด้วยวิธีนี้จะเข้าเฉพาะบัญชีแยกประเภท
> แต่ยังไม่มีใบแจ้งหนี้รายใบในระบบ ทำให้ **บัญชีคุมไม่ตรงกับบัญชีย่อย** และแดชบอร์ดจะขึ้นเตือนสีแดง
>
> ทางแก้: ออกใบแจ้งหนี้และใบตั้งหนี้ของรายการที่ยังค้างชำระเข้าระบบตามปกติ
> โดยใช้วันที่จริงของเอกสารเดิม แล้วไม่ต้องลงยอดลูกหนี้/เจ้าหนี้ในรายการยอดยกมาอีก

### 3.3 ตรวจหลังนำเข้า

- งบทดลอง ณ วันเริ่มระบบต้องตรงกับงบเดิมทุกบาท
- แถบบนซ้ายต้องเป็น **"● ระบบสมดุล"** สีเขียว

## ส่วนที่ 4 — สิ่งที่ระบบยังไม่มี

ต้องรู้ก่อนตัดสินใจใช้งานจริง เพื่อวางแผนรับมือ

| หัวข้อ | ทางออกชั่วคราว |
|---|---|
| ใบเสนอราคา · ใบสั่งซื้อ | ทำนอกระบบ แล้วอ้างเลขที่ในช่องหมายเหตุของใบแจ้งหนี้ |
| ใบลดหนี้ / ใบเพิ่มหนี้ | ลงบัญชีมือตามกฎ R-5 ใน [posting-rules.md](posting-rules.md) |
| หน้าจอเงินเดือน | รับยอดสรุปจากระบบเงินเดือนภายนอก ลงบัญชีมือตามกฎ PR-1 |
| ทะเบียนสินทรัพย์และค่าเสื่อมอัตโนมัติ | ลงบัญชีมือทุกสิ้นเดือนตามกฎ FA-2 |
| กระทบยอดธนาคาร | เทียบกับ statement เอง แล้วดูยอดบัญชีธนาคารที่หน้าตั้งค่า |
| พิมพ์ใบกำกับภาษี / 50 ทวิ เป็น PDF | สั่งพิมพ์จากเบราว์เซอร์ (มี print stylesheet ให้แล้ว) |
| ลืมรหัสผ่าน | ผู้จัดการบัญชีตั้งรหัสใหม่ให้ที่เมนูผู้ใช้งาน |
| **ผู้ดูแลคนเดียวลืมรหัสผ่าน** | ต้องตั้งใหม่ผ่านฐานข้อมูล (ดูข้อ 5) |

## ส่วนที่ 5 — งานดูแลระบบ

### ตั้งรหัสผ่านใหม่ให้ผู้ดูแลคนสุดท้าย

กรณีลืมรหัสผ่านและไม่มีใครเข้าระบบได้เลย

```bash
docker compose exec db psql -U postgres -d accounting -c "UPDATE acc.app_users SET password_hash='', must_change_password=TRUE WHERE username='admin';"
```

จากนั้นล้างผู้ใช้ทั้งหมดเพื่อให้ระบบกลับไปหน้าติดตั้งใหม่ (ข้อมูลบัญชียังอยู่ครบ)

```bash
docker compose exec db psql -U postgres -d accounting -c "DELETE FROM acc.app_users;"
```

> รายการบัญชีเดิมอ้างถึงผู้ใช้ที่ถูกลบ ฐานข้อมูลจะปฏิเสธถ้ามีการอ้างอิงอยู่
> กรณีนั้นให้ใช้วิธีตั้ง `password_hash` ใหม่แทน โดยสร้างค่าแฮชด้วยสคริปต์ในโฟลเดอร์ `web`

### ตรวจสุขภาพระบบประจำเดือน

```bash
docker compose exec db psql -U postgres -d accounting -c "SELECT * FROM acc.v_accounting_equation_check;"
docker compose exec db psql -U postgres -d accounting -c "SELECT * FROM acc.v_control_reconciliation;"
```

ทั้งสองต้องได้ผลต่างเป็น **0.00** · ถ้าไม่เป็นศูนย์ห้ามปิดงวด ต้องหาสาเหตุก่อน

### ดูว่าใครทำอะไรไว้บ้าง

```bash
docker compose exec db psql -U postgres -d accounting -c "SELECT changed_at, changed_by, table_name, action FROM acc.audit_log ORDER BY changed_at DESC LIMIT 30;"
```
