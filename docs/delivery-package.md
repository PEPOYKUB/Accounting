# ชุดส่งมอบลูกค้า — วิธีสร้างและวิธีดูแล

เอกสารนี้สำหรับ **ผู้พัฒนา** ไม่ใช่ลูกค้า
อธิบายว่าโฟลเดอร์ `D:\All Works_CO\Accounting-Setup\` คืออะไร สร้างขึ้นมาอย่างไร และจะสร้างใหม่เมื่อแก้โค้ดได้อย่างไร

---

## 1. ชุดส่งมอบคืออะไร

โฟลเดอร์ `Accounting-Setup` ขนาด **238 MB** เป็นชุดติดตั้งสำเร็จรูปที่ลูกค้าใช้ได้ทันที
ต่างจากโฟลเดอร์พัฒนา (`Accounting`) ตรงที่**ไม่ต้อง build และไม่ต้องโหลดอะไรจากอินเทอร์เน็ต**

| ไฟล์ / โฟลเดอร์ | คืออะไร |
|---|---|
| `accounting-images.tar` | 248,169,984 bytes — Docker image สองตัวรวมกัน (`accounting-web:1.0` + `postgres:16`) |
| `docker-compose.yml` | ใช้ `image:` ตรง ๆ ไม่มีส่วน `build` |
| `install.ps1` | ติดตั้งอัตโนมัติ 4 ขั้น — ตรวจ Docker → `docker load` → `compose up` → บอกลิงก์ |
| `save-backup.ps1` | สำรองข้อมูลเป็นไฟล์ `.dump` |
| `restore.ps1` | กู้คืนจากไฟล์สำรอง |
| `reset-password.ps1` | ตั้งรหัสผ่านใหม่เมื่อลืมจนเข้าไม่ได้ |
| `share.ps1` | แสดงลิงก์ LAN / Tailscale และเปิดไฟร์วอลล์ |
| `*.bat` 6 ไฟล์ | ปุ่มลัดชื่อภาษาไทยให้ดับเบิลคลิก |
| `อ่านก่อน.md` | เอกสารหน้าแรกสำหรับลูกค้า |
| `db/` | SQL 5 ไฟล์ — schema, ผังบัญชี, auth, exports, tests |
| `docs/` | คู่มือ 5 เล่ม |

**ไม่มีข้อมูลสาธิตในชุดนี้** — ไฟล์ `sample_data.sql`, `seed_demo_users.sql`, `docker-compose.demo.yml`, `demo-guide.md` ถูกตัดออกโดยตั้งใจ เพื่อไม่ให้ลูกค้าเผลอเปิดข้อมูลสมมติปนกับข้อมูลจริง (ไฟล์เหล่านี้ยังอยู่ในโฟลเดอร์พัฒนา)

## 2. สร้างชุดส่งมอบใหม่ — ทำเมื่อแก้โค้ดในโฟลเดอร์ `web`

ทั้งหมดสั่งจาก `D:\All Works_CO\Accounting`

### ขั้นที่ 1 — build image ใหม่

```bash
docker compose build --no-cache web
```

> `ALLOWED_ORIGINS` ถูกฝังตอน build (Next.js อ่าน `next.config` ตอน build ไม่ใช่ตอนรัน)
> ค่าปกติเป็นค่าว่าง ใช้ได้กับ localhost และ LAN
> จะใช้ tunnel ต้องแก้ `docker-compose.yml` บรรทัด `ALLOWED_ORIGINS:` แล้ว build ใหม่

### ขั้นที่ 2 — ตั้งชื่อ tag ให้ตรงกับที่ compose ฝั่งลูกค้าเรียก

```bash
docker tag accounting-web:latest accounting-web:1.0
```

> ชื่อที่ `docker compose build` ตั้งให้จะเป็น `accounting-web` หรือ `<ชื่อโฟลเดอร์>-web`
> ตรวจด้วย `docker images` ก่อนเสมอ แล้ว tag ให้เป็น `accounting-web:1.0`

### ขั้นที่ 3 — บันทึกทั้งสอง image เป็นไฟล์เดียว

```bash
docker save -o "D:\All Works_CO\Accounting-Setup\accounting-images.tar" accounting-web:1.0 postgres:16
```

ใช้เวลาประมาณ 1-2 นาที ได้ไฟล์ประมาณ 240 MB

### ขั้นที่ 4 — คัดลอกไฟล์ที่เปลี่ยนไปด้วย

ถ้าแก้ SQL หรือคู่มือ ต้องคัดลอกทับด้วย เพราะไฟล์เหล่านี้ไม่ได้อยู่ใน image

```bash
robocopy "D:\All Works_CO\Accounting\db" "D:\All Works_CO\Accounting-Setup\db" /XF sample_data.sql seed_demo_users.sql
robocopy "D:\All Works_CO\Accounting\docs" "D:\All Works_CO\Accounting-Setup\docs" /XF demo-guide.md
```

### ขั้นที่ 5 — ตรวจก่อนส่ง

```bash
docker compose -f "D:\All Works_CO\Accounting-Setup\docker-compose.yml" down -v
docker rmi accounting-web:1.0 postgres:16 -f
```

แล้วรัน `install.ps1` ในโฟลเดอร์ `Accounting-Setup` ต้องขึ้น `Loaded image` ครบสองบรรทัด
และ `http://localhost:3100/setup` ต้องตอบ 200

## 3. กฎที่ต้องระวังเวลาแก้สคริปต์

ข้อเหล่านี้เคยพังมาแล้วจริง ๆ แก้แล้วต้องตรวจซ้ำทุกครั้ง

| กฎ | เหตุผล |
|---|---|
| **`.ps1` ต้องเป็น UTF-8 มี BOM** | PowerShell 5.1 อ่านภาษาไทยไม่ออกถ้าไม่มี BOM แล้วสคริปต์จะพังทั้งไฟล์ |
| **`.bat` ต้องเป็น ASCII ล้วน + CRLF** | เนื้อในต้องไม่มีภาษาไทย (ชื่อไฟล์เป็นไทยได้) และต้องมี `chcp 65001` |
| **ห้ามใช้ `$ErrorActionPreference = 'Stop'`** | docker เขียนความคืบหน้าลง stderr เป็นปกติ PowerShell 5.1 จะแปลงเป็น error แล้วหยุดทั้งที่คำสั่งสำเร็จ — ให้ใช้ `'Continue'` แล้วตรวจ `$LASTEXITCODE` เอง |
| **ห้ามใช้ `$` ในโค้ด JS ที่ส่งผ่าน `node -e` ใน PowerShell** | PowerShell กิน `$32768` เป็นชื่อตัวแปร — ใช้ `String.fromCharCode(36)` แทน |
| **`psql -c` ไม่แทนค่าตัวแปร `-v`** | ต้องส่ง SQL ทาง stdin แทน |
| **ห้ามส่งข้อมูลไบนารีผ่าน pipe ของ PowerShell** | ไฟล์ dump จะเสีย — ใช้ `pg_dump -f` ในคอนเทนเนอร์แล้ว `docker cp` ออกมา |
| **อย่าตั้งชื่อไฟล์ว่า `backup.ps1`** | Windows Defender เคยบล็อกชื่อนี้จนอ่าน/ลบ/เปลี่ยนชื่อไม่ได้ จึงใช้ `save-backup.ps1` |

## 4. ลูกค้าต้องทำอะไรบ้าง

1. ติดตั้ง **Docker Desktop** (โปรแกรมเดียวที่ต้องโหลด — ฟรี)
2. แตกไฟล์แล้วดับเบิลคลิก **`ติดตั้ง.bat`** รอ 2-4 นาที
3. เปิด `http://localhost:3100` แล้วกรอกข้อมูลกิจการกับสร้างผู้ดูแลคนแรก

จากนั้นแดชบอร์ดจะบอกเองว่าเหลือตั้งค่าอะไรอีก (บัญชีธนาคาร ลูกค้า ผู้ขาย)

**ให้มือถือใช้งาน:** รัน `.\share.ps1 -OpenFirewall` แบบ Run as Administrator ครั้งเดียว
แล้วส่งลิงก์ `192.168.x.x:3100` ให้ — มือถือเปิด `localhost` ไม่ได้

## 5. เรื่องที่ต้องบอกลูกค้าให้ชัด

| เรื่อง | ต้องบอกว่า |
|---|---|
| **สำรองข้อมูล** | ข้อมูลอยู่ในเครื่องนั้นเครื่องเดียว ต้องกด `สำรองข้อมูล.bat` ทุกสัปดาห์ **แล้วคัดลอกไฟล์ออกไปเก็บที่อื่นด้วย** กฎหมายให้เก็บ 5 ปี |
| **เครื่องต้องเปิดค้าง** | และต้องล็อกอิน Windows ค้างไว้ด้วย เพราะ Docker Desktop เริ่มทำงานเมื่อมีคนล็อกอินเท่านั้น |
| **ใช้ในวง LAN เท่านั้น** | เป็น http ธรรมดา ไม่ได้เข้ารหัส ห้ามเปิดพอร์ต 3100 ออกอินเทอร์เน็ต |
| **ให้นักบัญชีตรวจก่อน** | ส่ง `docs/posting-rules.md` ให้นักบัญชีอ่านก่อนเริ่มลงข้อมูลจริง |
| **ยอดยกมา** | บันทึกผ่านเมนู ลงบัญชีมือ เลือกประเภท "ยอดยกมา" ดู `docs/production-checklist.md` ส่วนที่ 3 |
| **สิ่งที่ระบบยังไม่มี** | ใบเสนอราคา ใบสั่งซื้อ เงินมัดจำ และ Payroll แบบคำนวณเอง — ดู `docs/production-checklist.md` ส่วนที่ 4 |

## 6. ผลการทดสอบชุดนี้

ทดสอบจากเครื่องที่ลบ image และ volume ออกหมดแล้ว เหมือนเครื่องลูกค้าที่เพิ่งลง Docker

| ทดสอบ | ผล |
|---|---|
| `install.ps1` จากเครื่องเปล่า | ผ่าน — `Loaded image` ครบ 2 บรรทัด, container ขึ้น healthy ทั้งคู่ |
| ฐานข้อมูลเริ่มต้น | ผังบัญชี 79 บัญชี · ผู้ใช้ 0 · ไม่มีข้อมูลสมมติ |
| หน้าติดตั้งครั้งแรก | `/setup` ตอบ 200 · บันทึกกิจการ ปีบัญชี และผู้ดูแลได้ครบ |
| เข้าสู่ระบบและใช้งาน | ผ่าน — แดชบอร์ดขึ้นเช็กลิสต์ 3 ขั้นที่เหลือ ตัวเลขทุกช่องเป็น 0.00 |
| แสดงผลบนมือถือ 375px | ผ่าน — เมนูล่าง 5 ปุ่มครบ ไม่มีการเลื่อนแนวนอน |
| `save-backup.ps1` | ผ่าน — ได้ไฟล์ `.dump` 186,930 bytes |
| กู้คืนจากไฟล์สำรอง | ผ่าน — ผู้ใช้ 0→1, ผังบัญชี 55→79, mapping 0→38, ชื่อกิจการกลับมา, 0 error |
| `reset-password.ps1` | ผ่าน — เข้าระบบด้วยรหัสชั่วคราวได้ แล้วถูกบังคับตั้งรหัสใหม่ทันที |
| BOM ของ `.ps1` ทั้ง 5 ไฟล์ | ผ่าน — `efbbbf` ครบทุกไฟล์ |
| `.bat` ทั้ง 6 ไฟล์ | ผ่าน — ASCII + CRLF ครบทุกไฟล์ |

## 7. สิ่งที่ยังทดสอบไม่ได้

| เรื่อง | เหตุผล |
|---|---|
| **การเขียนลง Google Sheets จริง** | ต้องใช้ Service Account ของลูกค้า · ทดสอบได้แค่ว่า JWT ที่เซ็นส่งถึง Google แล้ว Google ตอบกลับ (`invalid_grant: account not found`) ซึ่งพิสูจน์ว่ารูปแบบและลายเซ็นถูกต้อง |
