# กฎการลงบัญชีอัตโนมัติ (Posting Rules) — ฉบับเต็ม
### ธุรกิจบริการ | TFRS for NPAEs | ใช้คู่กับ `db/schema.sql`

> เอกสารนี้คือ **สเปคสำหรับ Journal Engine** — นักพัฒนาต้อง implement ให้ตรงทุกกฎ และนักบัญชีต้องใช้ตรวจรับงาน
> ทุกกฎอ้างบัญชีด้วย **key จากตาราง `acc.account_mappings`** ไม่ใช่รหัสบัญชีตรง ๆ (รหัสในวงเล็บใส่ไว้เพื่อให้อ่านง่ายเท่านั้น)

---

## 0. หลักการที่ใช้ตัดสินทุกกฎในเอกสารนี้

| # | หลักการ | ผลต่อการออกแบบ |
|---|---|---|
| 0.1 | **จุดรับผิดในการเสีย VAT ของบริการ = วันที่ได้รับชำระเงิน** (ป.รัษฎากร ม.78/1) | ตอนออกใบแจ้งหนี้ลง **พักภาษีขาย** ก่อน โอนเป็นภาษีขายจริงตอนรับเงินและออกใบกำกับภาษี |
| 0.2 | **ภาษีซื้อใช้สิทธิได้เมื่อได้รับใบกำกับภาษีตัวจริง** | ค่าบริการจากผู้ขาย (ได้ใบกำกับตอนจ่าย) ลง **พักภาษีซื้อ** ก่อน / ค่าสินค้า (ได้ใบกำกับพร้อมของ) ลงภาษีซื้อได้ทันที ควบคุมด้วยฟิลด์ `ap_bills.vat_timing` |
| 0.3 | **ภาษีหัก ณ ที่จ่ายเกิดเมื่อ "จ่ายเงิน" ไม่ใช่เมื่อ "ตั้งหนี้"** | ห้ามลง WHT ในรายการตั้งหนี้เด็ดขาด |
| 0.4 | **WHT คำนวณจากฐานก่อน VAT เสมอ** | `wht = subtotal × rate` ไม่ใช่ `total × rate` |
| 0.5 | **บริษัทเป็นผู้ให้บริการ จึงถูกลูกค้าหัก ณ ที่จ่าย 3%** | ต้องบันทึกเป็น **สินทรัพย์** `WHT_RECEIVABLE (1160)` เพื่อใช้เครดิตภาษีตอนยื่น ภงด.50 |
| 0.6 | **รับรู้รายได้ตามเกณฑ์คงค้าง** (ให้บริการเสร็จแล้วรับรู้ แม้ยังไม่วางบิล) | ต้องมีรายการ `ACCRUED_REVENUE (1120)` และรายการกลับบัญชีต้นงวดถัดไป |
| 0.7 | **JE ที่ POSTED แล้วห้ามแก้** | ทุกการยกเลิก = สร้าง Reversing Entry ใหม่ (ดู §9.1) |
| 0.8 | **ปัดเศษที่ระดับใบเอกสาร ไม่ใช่ระดับบรรทัด** | ผลต่างที่เหลือเข้า `ROUNDING_DIFF (5195)` ได้ไม่เกินค่าใน `system_settings.ROUNDING_TOLERANCE` |

**สัญลักษณ์ในเอกสาร**
`ST` = ยอดก่อนภาษี (subtotal) · `VAT` = ภาษีมูลค่าเพิ่ม · `TOT` = ST + VAT · `WHT` = ภาษีหัก ณ ที่จ่าย

# 1. วงจรรายรับ (Revenue Cycle)

## R-1 · ออกใบแจ้งหนี้/ใบวางบิล (Invoice)

| | |
|---|---|
| **เอกสารต้นทาง** | `ar_invoices` (status → `POSTED`) |
| **เงื่อนไขก่อน post** | เอกสารต้องผ่านการอนุมัติ · งวดของ `issue_date` ต้อง `OPEN` |
| **source_type** | `SALES_INVOICE` |

```
Dr. AR_TRADE              (1100) ลูกหนี้การค้า            TOT
    Cr. SERVICE_REVENUE   (4000) รายได้จากการให้บริการ         ST
    Cr. OUTPUT_VAT_SUSPENSE (2101) พักภาษีขาย                  VAT
```

**ข้อควรระวัง**
- ใช้ `2101 พักภาษีขาย` **ไม่ใช่** `2100 ภาษีขาย` — เพราะบริการยังไม่ถึงจุดรับผิด รายการนี้จึง **ยังไม่เข้ารายงานภาษีขาย** และยังไม่ต้องยื่น ภพ.30
- บัญชีรายได้ดึงจาก `ar_invoice_lines.revenue_account_id` รายบรรทัด (ใบเดียวลงได้หลายบัญชีรายได้/หลาย cost center)
- **ยังไม่บันทึก WHT** ที่ขั้นนี้ แม้จะรู้ว่าลูกค้าจะหัก — เพราะยังไม่ได้รับเงิน

**Side effects**
- `ar_invoices.balance_due = total_amount`
- **ไม่** เพิ่มแถวใน `vat_output_items`

---

## R-2 · รับชำระเงินจากลูกค้า + ออกใบกำกับภาษี/ใบเสร็จ

| | |
|---|---|
| **เอกสารต้นทาง** | `ar_receipts` + `ar_receipt_allocations` |
| **source_type** | `SALES_RECEIPT` |

```
Dr. BANK_DEFAULT          (1020) เงินฝากธนาคาร          TOT − WHT
Dr. WHT_RECEIVABLE        (1160) ภาษีถูกหัก ณ ที่จ่าย        WHT
    Cr. AR_TRADE          (1100) ลูกหนี้การค้า                 TOT

-- โอนภาษีขายจากบัญชีพักเข้าบัญชีจริง (ในใบสำคัญเดียวกัน)
Dr. OUTPUT_VAT_SUSPENSE   (2101) พักภาษีขาย                 VAT
    Cr. OUTPUT_VAT        (2100) ภาษีขาย                       VAT
```

**ตัวอย่างตัวเลข** — ค่าบริการ 100,000 · VAT 7% · ลูกค้าหัก 3%

| บัญชี | เดบิต | เครดิต |
|---|---:|---:|
| 1020 เงินฝากธนาคาร | 104,000.00 | |
| 1160 ภาษีถูกหัก ณ ที่จ่าย | 3,000.00 | |
| 1100 ลูกหนี้การค้า | | 107,000.00 |
| 2101 พักภาษีขาย | 7,000.00 | |
| 2100 ภาษีขาย | | 7,000.00 |
| **รวม** | **114,000.00** | **114,000.00** |

**ข้อควรระวัง**
- `WHT = 100,000 × 3% = 3,000` คิดจาก **ฐานก่อน VAT** ไม่ใช่ 107,000
- ถ้ารับชำระบางส่วน ให้โอนพักภาษีขาย **ตามสัดส่วนที่รับจริง** ไม่ใช่ทั้งจำนวน
- ถ้าธนาคารหักค่าธรรมเนียมโอน ให้เพิ่มบรรทัด `Dr. BANK_CHARGE (5190)` และลดยอดเงินเข้า

**Side effects**
- เพิ่มแถวใน **`vat_output_items`** (นี่คือจุดที่รายการเข้ารายงานภาษีขาย)
- อัปเดต `ar_invoices.paid_amount / balance_due / status` ตาม allocation ทุกใบ
- สร้างแถวใน `wht_received` สถานะ `is_document_received = FALSE` เพื่อติดตามทวงหนังสือรับรองจากลูกค้า

## R-3 · รับเงินล่วงหน้า / เงินมัดจำ (ยังไม่ได้ให้บริการ)

```
Dr. BANK_DEFAULT          (1020)                        รับจริง
Dr. WHT_RECEIVABLE        (1160)                          WHT
    Cr. ADVANCE_FROM_CUSTOMER (2020) เงินรับล่วงหน้า          ST
    Cr. OUTPUT_VAT        (2100) ภาษีขาย                      VAT
```

> **VAT เกิดทันทีที่รับเงิน แม้ยังไม่ได้ให้บริการ** — จุดนี้ต่างจาก R-1 จึงลง `2100` ตรง ๆ ไม่ผ่านบัญชีพัก
> เมื่อให้บริการเสร็จและออกใบแจ้งหนี้จริง ให้กลับรายการ: `Dr. 2020 / Cr. 4000` (ไม่มี VAT ซ้ำ)

---

## R-4 · รายได้ค้างรับ (ให้บริการแล้ว ยังไม่วางบิล) — ปรับปรุงสิ้นงวด

```
Dr. ACCRUED_REVENUE       (1120) รายได้ค้างรับ              ST
    Cr. SERVICE_REVENUE   (4000) รายได้จากการให้บริการ         ST
```
- **ไม่มี VAT** เพราะยังไม่ถึงจุดรับผิดทั้งการวางบิลและการรับเงิน
- ต้องตั้ง **Reversing Entry อัตโนมัติวันแรกของงวดถัดไป** มิฉะนั้นรายได้จะถูกรับรู้ซ้ำเมื่อออกใบแจ้งหนี้จริง

---

## R-5 · ใบลดหนี้ (Credit Note)

**กรณี ก — ลูกค้ายังไม่ได้ชำระ** (ภาษีขายยังอยู่ในบัญชีพัก)
```
Dr. SALES_DISCOUNT        (4090) ส่วนลดจ่ายและรับคืน         ST
Dr. OUTPUT_VAT_SUSPENSE   (2101) พักภาษีขาย                 VAT
    Cr. AR_TRADE          (1100) ลูกหนี้การค้า                 TOT
```

**กรณี ข — ลูกค้าชำระแล้ว** (ภาษีขายนำส่งไปแล้ว)
```
Dr. SALES_DISCOUNT        (4090)                            ST
Dr. OUTPUT_VAT            (2100) ภาษีขาย                     VAT
    Cr. AR_TRADE / BANK   (1100/1020)                        TOT
```
- กรณี ข ต้องเพิ่มแถว **ยอดติดลบ** ใน `vat_output_items` ของงวดที่ออกใบลดหนี้ (ไม่ใช่ไปแก้งวดเดิม)
- ใบลดหนี้ต้องอ้างเลขที่ใบกำกับภาษีเดิมเสมอ (`original_tax_invoice_no`) ตามที่กฎหมายกำหนด

[ตั้งค่าเผื่อ - สิ้นงวด]
Dr. DOUBTFUL_DEBT         (5180) หนี้สงสัยจะสูญ           ประมาณการ

[ตัดหนี้สูญจริง — ต้องเข้าเงื่อนไขกฎกระทรวง ฉบับ 186 จึงถือเป็นรายจ่ายทางภาษีได้]
Dr. AR_ALLOWANCE          (1110)                          จำนวนที่ตัด
    Cr. AR_TRADE          (1100)                          จำนวนที่ตัด
```

# 2. วงจรรายจ่าย (Expenditure Cycle)

## P-1 · ตั้งหนี้ผู้ขาย — ค่าบริการ (`vat_timing = ON_PAYMENT`)

```
Dr. <บัญชีจาก ap_bill_lines.expense_account_id>            ST
Dr. INPUT_VAT_SUSPENSE    (1151) พักภาษีซื้อ                VAT
    Cr. AP_TRADE          (2000) เจ้าหนี้การค้า                TOT   ← เต็มจำนวน
```

> 🔴 **จุดที่เอกสารสถาปัตยกรรมฉบับเดิมผิด**: เดิมหัก WHT ตรงนี้และเครดิตเจ้าหนี้ด้วยยอดสุทธิ
> ผลคือ **ยอดเจ้าหนี้ในงบดุลต่ำกว่าความจริง** และนำส่งภาษีผิดงวด — เจ้าหนี้ต้องเป็น TOT เต็มจำนวนเสมอ

## P-2 · ตั้งหนี้ผู้ขาย — ค่าสินค้า/ได้ใบกำกับภาษีทันที (`vat_timing = ON_INVOICE`)

```
Dr. <ค่าใช้จ่าย / สินทรัพย์>                                ST
Dr. INPUT_VAT             (1150) ภาษีซื้อ                   VAT
    Cr. AP_TRADE          (2000)                             TOT
```
→ เพิ่มแถวใน `vat_input_items` ทันทีที่ขั้นนี้

## P-3 · จ่ายชำระเจ้าหนี้ + หักภาษี ณ ที่จ่าย

```
Dr. AP_TRADE              (2000) เจ้าหนี้การค้า              TOT
    Cr. WHT_PAYABLE_PND53 (2202) ภาษีหัก ณ ที่จ่ายค้างนำส่ง     WHT
    Cr. BANK_DEFAULT      (1020) เงินฝากธนาคาร            TOT − WHT

-- ถ้าใบตั้งหนี้เป็น ON_PAYMENT ให้โอนภาษีซื้อในใบสำคัญเดียวกัน
Dr. INPUT_VAT             (1150) ภาษีซื้อ                    VAT
    Cr. INPUT_VAT_SUSPENSE (1151) พักภาษีซื้อ                  VAT
```

**ตัวอย่างตัวเลข** — ค่าจ้างผู้รับเหมาช่วง 50,000 · VAT 7% · หัก 3%

| บัญชี | เดบิต | เครดิต |
|---|---:|---:|
| 2000 เจ้าหนี้การค้า | 53,500.00 | |
| 2202 ภงด.53 ค้างนำส่ง | | 1,500.00 |
| 1020 เงินฝากธนาคาร | | 52,000.00 |
| 1150 ภาษีซื้อ | 3,500.00 | |
| 1151 พักภาษีซื้อ | | 3,500.00 |
| **รวม** | **57,000.00** | **57,000.00** |

**การเลือกบัญชี WHT ค้างนำส่ง**

| ผู้รับเงิน | แบบยื่น | บัญชี |
|---|---|---|
| พนักงาน (เงินเดือน) | ภงด.1 | `WHT_PAYABLE_PND1` (2200) |
| บุคคลธรรมดา | ภงด.3 | `WHT_PAYABLE_PND3` (2201) |
| นิติบุคคล | ภงด.53 | `WHT_PAYABLE_PND53` (2202) |

**Side effects**
- เพิ่มแถวใน `vat_input_items` (สำหรับใบ `ON_PAYMENT`)
- สร้าง `wht_certificates` เพื่อออกหนังสือรับรองให้ผู้ขาย
- อัปเดต `ap_bills.paid_amount / balance_due / status` ตาม allocation

## P-4 · จ่ายสด (ไม่ผ่านการตั้งหนี้)

รวม P-1 กับ P-3 เป็นใบสำคัญเดียว:
```
Dr. <ค่าใช้จ่าย>                                            ST
Dr. INPUT_VAT             (1150)                            VAT
    Cr. WHT_PAYABLE_xxx   (22xx)                             WHT
    Cr. BANK_DEFAULT      (1020)                        TOT − WHT
```

## P-5 · ค่าใช้จ่ายค้างจ่าย (ปรับปรุงสิ้นงวด)

```
Dr. <ค่าใช้จ่าย>                                       ประมาณการ
    Cr. ACCRUED_EXPENSE   (2010) ค่าใช้จ่ายค้างจ่าย        ประมาณการ

- ตั้ง Reversing Entry วันแรกของงวดถัดไป

## P-7 · ภาษีซื้อต้องห้าม (ค่ารับรอง, รถยนต์นั่ง ฯลฯ)

```
Dr. <ค่าใช้จ่าย>                                            ST
Dr. NON_CLAIMABLE_VAT     (5196) ภาษีซื้อต้องห้าม           VAT   ← เป็นค่าใช้จ่าย ไม่ใช่สินทรัพย์

# 3. เงินเดือน (Payroll — รับยอดสรุปจากระบบภายนอก)

## PR-1 · บันทึกเงินเดือนประจำเดือน (1 JE ต่อ 1 งวด)

| | |
|---|---|
| **เอกสารต้นทาง** | `payroll_batches` (นำเข้าไฟล์สรุปจากระบบเงินเดือน + แนบไฟล์เป็นหลักฐาน) |
| **source_type** | `PAYROLL` |
| **เงื่อนไขก่อน post** | ผ่าน CHECK `payroll_reconciles` แล้วเท่านั้น |

```
Dr. SALARY_EXPENSE        (5110) เงินเดือนและค่าแรง       gross_salary
Dr. SSO_EXPENSE           (5112) ประกันสังคม-นายจ้าง      sso_employer
    Cr. WHT_PAYABLE_PND1  (2200) ภงด.1 ค้างนำส่ง             wht_pnd1
    Cr. SSO_PAYABLE       (2210) ประกันสังคมค้างนำส่ง    sso_emp + sso_empr
    Cr. BANK_DEFAULT      (1020) เงินฝากธนาคาร               net_paid
```

**ตัวอย่างตัวเลข** — เงินเดือนรวม 300,000 · ประกันสังคมฝ่ายละ 7,500 · ภงด.1 8,000

| บัญชี | เดบิต | เครดิต |
|---|---:|---:|
| 5110 เงินเดือนและค่าแรง | 300,000.00 | |
| 5112 ประกันสังคม-นายจ้าง | 7,500.00 | |
| 2200 ภงด.1 ค้างนำส่ง | | 8,000.00 |
| 2210 ประกันสังคมค้างนำส่ง | | 15,000.00 |
| 1020 เงินฝากธนาคาร | | 284,500.00 |
| **รวม** | **307,500.00** | **307,500.00** |

> **จุดที่มักผิด**: `2210` ต้องเครดิต **ทั้งสองฝ่ายรวมกัน (15,000)** เพราะบริษัทเป็นผู้นำส่งทั้งก้อน
> ส่วนที่เป็นค่าใช้จ่ายของบริษัทคือฝ่ายนายจ้างเท่านั้น (7,500)

# 4. สินทรัพย์ถาวร

## FA-1 · ซื้อสินทรัพย์
```

Dr. INPUT_VAT / INPUT_VAT_SUSPENSE                          VAT
    Cr. AP_TRADE / BANK                                     TOT

→ สร้างแถวใน `fixed_assets` พร้อมกำหนด `in_service_date` (วันเริ่มคิดค่าเสื่อม อาจต่างจากวันซื้อ)

## FA-2 · ค่าเสื่อมราคาประจำเดือน (งานอัตโนมัติทุกสิ้นเดือน)
```
Dr. DEPRECIATION_EXPENSE  (5160) ค่าเสื่อมราคา          รวมทุกสินทรัพย์
    Cr. <ค่าเสื่อมราคาสะสม 15x1>                         แยกตามประเภท
```
- **วิธีเส้นตรง**: `(cost − salvage_value) ÷ useful_life_years ÷ 12`
- คิดค่าเสื่อมตามจำนวนวันในเดือนแรกที่เริ่มใช้งาน (pro-rate)
- หยุดคิดเมื่อ `accumulated_depreciation = cost − salvage_value` (บังคับด้วย CHECK `fa_accum_not_over`)
- **กันคิดซ้ำ** ด้วย UNIQUE `(fixed_asset_id, period_id)` ใน `depreciation_entries`

# 5. ภาษี

## T-1 · ปิดยอดภาษีมูลค่าเพิ่มสิ้นเดือน (ภพ.30)

```
Dr. OUTPUT_VAT            (2100) ภาษีขาย                 ยอดทั้งเดือน
    Cr. INPUT_VAT         (1150) ภาษีซื้อ                 ยอดทั้งเดือน
    Cr. VAT_PAYABLE       (2110) ภาษีมูลค่าเพิ่มค้างชำระ       ผลต่าง
```
กรณีภาษีซื้อมากกว่าภาษีขาย ให้กลับด้าน โดยเดบิต `VAT_REFUNDABLE (1155)` แทน

```
[ชำระภายในวันที่ 15 ของเดือนถัดไป]
Dr. VAT_PAYABLE           (2110)
    Cr. BANK_DEFAULT      (1020)
```

**การตรวจสอบก่อนยื่น (บังคับ)**
1. ยอดเดบิตรวมของ `2100` ในงวด = ผลรวม `vat_output_items.vat_amount` ของงวดนั้น
2. ยอดเครดิตรวมของ `1150` ในงวด = ผลรวม `vat_input_items.vat_amount` เฉพาะ `is_claimable = TRUE`
3. หลังปิดยอด บัญชี `2100` และ `1150` ต้องมียอดคงเหลือเป็น **ศูนย์**
4. ยอดคงเหลือใน `2101 พักภาษีขาย` ต้องเท่ากับ VAT ของใบแจ้งหนี้ที่ยังไม่ได้รับชำระ

## T-2 · นำส่งภาษีหัก ณ ที่จ่าย (ภงด.3 / 53 — ภายในวันที่ 7 ของเดือนถัดไป)

    Cr. CIT_PAYABLE       (2300)

[ชำระ — ใช้เครดิตภาษีที่ถูกหักไว้ระหว่างปี]

# 7. ปิดงวดและปิดปี

## C-0 · เช็กลิสต์ก่อนปิดงวด (บังคับโดยฟังก์ชัน `acc.close_period()`)
1. ไม่มี JE สถานะ `DRAFT` ค้างในงวด
2. `v_accounting_equation_check.out_of_balance = 0`
3. `v_control_reconciliation.difference = 0` ทั้งลูกหนี้และเจ้าหนี้
4. กระทบยอดธนาคารทุกบัญชีแล้ว (`bank_reconciliations.is_balanced = TRUE`)
5. คิดค่าเสื่อมราคาครบทุกสินทรัพย์ในงวด
6. ปิดยอด VAT (T-1) แล้ว
7. บันทึกรายการปรับปรุงคงค้าง (R-4, P-5, P-6) แล้ว

## C-1 ~ C-3 · ปิดบัญชีสิ้นปี (ทำเฉพาะงวดสุดท้ายของปีบัญชี)

# 9. กฎการตรวจสอบที่ระบบต้องบังคับ

## 9.1 การแก้ไขและยกเลิก
| สถานะเอกสาร | แก้ไขได้ | วิธียกเลิก |
|---|---|---|
| `DRAFT` | ✓ แก้ได้อิสระ | ลบได้ |
| `POSTED` | ✗ **ห้ามเด็ดขาด** (บังคับด้วย trigger) | สร้าง Reversing Entry `source_type = REVERSAL` ที่กลับด้าน Dr/Cr ทุกบรรทัด แล้วผูก `reverses_entry_id` / `reversed_by_entry_id` |

**วันที่ของ Reversing Entry**: ถ้างวดเดิมยัง `OPEN` ให้ใช้วันเดิม · ถ้างวดเดิมปิดแล้วให้ใช้ **วันแรกของงวดปัจจุบัน** — ห้ามเปิดงวดที่ปิดไปแล้วเพื่อแก้ตัวเลข

## 9.2 ลำดับการบันทึกที่ระบบบังคับ (สำคัญสำหรับนักพัฒนา)

Journal Entry ต้องสร้างเป็น **สองขั้นในทรานแซกชันเดียว** เสมอ:

```
BEGIN;
  1. INSERT journal_entries (status = 'DRAFT')      -- ระบบปฏิเสธถ้า insert เป็น POSTED ตรง ๆ
  2. INSERT journal_entry_lines ทุกบรรทัด
  3. UPDATE journal_entries SET status = 'POSTED', approved_by = ..., posted_at = now()
COMMIT;                                             -- ตรวจ Dr = Cr ที่จังหวะนี้
```

เหตุผล: trigger ความคงทนห้ามเพิ่มบรรทัดให้ใบที่ POSTED แล้ว จึงต้องใส่บรรทัดให้ครบก่อนเปลี่ยนสถานะ
และการตรวจสมดุลจะทำเฉพาะใบที่ POSTED เท่านั้น — ใบร่างระหว่างแก้ไขยังไม่สมดุลได้เป็นเรื่องปกติ

## 9.3 กฎที่บังคับที่ระดับฐานข้อมูล (แก้ผ่านโค้ดแอปไม่ได้)
| # | กฎ | กลไก |
|---|---|---|

| 4 | ห้ามลงบัญชีในงวดที่ไม่ใช่ `OPEN` | `trg_je_period_guard` |

# 10. ชุดทดสอบขั้นต่ำที่ต้องมี (Invariant Tests)

ระบบบัญชีต้องมีเทสต์เหล่านี้รันอัตโนมัติทุกครั้งที่แก้โค้ด:
