# ชุดสาธิตระบบบัญชี — คู่มือสำหรับผู้ตรวจสอบ

เอกสารนี้สำหรับผู้ที่ได้รับชุดสาธิตไปทดลองใช้และประเมินระบบ

---

## 1. ติดตั้งและเปิดใช้งาน

**สิ่งที่ต้องมี:** Docker Desktop (Windows / macOS / Linux) เท่านั้น ไม่ต้องติดตั้งฐานข้อมูลหรือ Node.js

```bash
docker compose up -d --build
```

ครั้งแรกใช้เวลาประมาณ 2-4 นาที (ดาวน์โหลดและ build) ครั้งต่อไปเปิดได้ในไม่กี่วินาที

เมื่อขึ้นข้อความ `accounting-web  Started` แล้ว เปิดเบราว์เซอร์ไปที่

**http://localhost:3100**

ตรวจสถานะได้ด้วย

```bash
docker compose ps
```

ทั้งสองบริการต้องขึ้น `healthy`

### คำสั่งที่ใช้บ่อย

| ต้องการ | คำสั่ง |
|---|---|
| ปิดระบบ (ข้อมูลยังอยู่) | `docker compose down` |
| เปิดใหม่ | `docker compose up -d` |
| ดูบันทึกการทำงาน | `docker compose logs -f web` |
| **ล้างทุกอย่างเริ่มใหม่** | `docker compose down -v` แล้ว `docker compose up -d --build` |

### เปิดบนมือถือ

ระบบออกแบบให้ใช้บนมือถือเป็นหลัก ตารางจะกลายเป็นการ์ดทีละรายการ ฟอร์มเรียงลงมาทีละช่อง
มีแถบเมนูล่างแบบแอป และปุ่มบันทึกลอยอยู่ล่างจอ

**มือถือเปิด `http://localhost:3100` ไม่ได้** เพราะ localhost หมายถึงตัวเครื่องมือถือเอง
ต้องใช้ลิงก์จากคำสั่ง `.\share.ps1` — `http://192.168.x.x:3100` สำหรับวงแลนเดียวกัน
หรือลิงก์ tunnel สำหรับคนนอกออฟฟิศ · วิธีทำอยู่ใน [getting-started.md ข้อ 3](getting-started.md)

**ติดตั้งเป็นแอปบนหน้าจอโฮมได้** — iPhone: ปุ่มแชร์ → เพิ่มไปยังหน้าจอโฮม ·
Android: จุดสามจุด → เพิ่มลงในหน้าจอหลัก · เปิดแล้วเต็มจอเหมือนแอปจริง

## 4. แนวทางการตรวจสอบ (ประมาณ 30 นาที)

### ขั้นที่ 1 — ดูภาพรวม (3 นาที)

เข้าสู่ระบบด้วย `somchai` แล้วดูแดชบอร์ด

**สิ่งที่ควรสังเกต:** ป้าย **"● ระบบสมดุล"** สีเขียวมุมบนซ้าย
ระบบตรวจสมการบัญชีและกระทบยอดบัญชีคุมกับบัญชีย่อยให้อัตโนมัติทุกครั้งที่โหลดหน้า
ถ้าตัวเลขเพี้ยนแม้บาทเดียวจะเปลี่ยนเป็นสีแดงทันที

### ขั้นที่ 2 — ทดลองออกใบแจ้งหนี้ (5 นาที)

รายรับ → ใบแจ้งหนี้ → **+ ออกใบแจ้งหนี้**

กรอกอะไรก็ได้ เช่น ค่าที่ปรึกษา 100,000 บาท VAT 7% แล้วกดบันทึก

จากนั้นคลิก **เลขที่ใบสำคัญ** ในคอลัมน์ขวาสุด จะเห็นรายการบัญชีที่ระบบสร้างให้

```
Dr ลูกหนี้การค้า        107,000
   Cr รายได้จากการให้บริการ    100,000
   Cr พักภาษีขาย                7,000   ← ยังไม่ใช่ภาษีขาย
```

**จุดที่ควรตรวจ:** VAT เข้า **"พักภาษีขาย"** ไม่ใช่ "ภาษีขาย"
เพราะธุรกิจบริการมีจุดรับผิดทางภาษีเมื่อ**รับเงิน** ไม่ใช่เมื่อวางบิล — ตรวจได้ที่เมนูรายงานภาษี ยอดยังไม่ขึ้น

### ขั้นที่ 3 — รับชำระเงินบางส่วน (5 นาที)

รายรับ → รับชำระเงิน → **+ รับชำระเงิน** → เลือกลูกค้าที่เพิ่งออกใบแจ้งหนี้

ติ๊กใบแจ้งหนี้ แล้ว**แก้ยอดรับให้เหลือครึ่งเดียว** (เช่น 53,500)

**จุดที่ควรตรวจ:** ระบบคำนวณให้ทันที
- โอนพักภาษีขายเข้าภาษีขาย **ตามสัดส่วนที่รับจริงเท่านั้น** (3,500 ไม่ใช่ 7,000)
- ภาษีหัก ณ ที่จ่าย 3% คำนวณจาก**ฐานก่อน VAT** (50,000 × 3% = 1,500)
- เงินเข้าบัญชีจริง = 53,500 − 1,500 = 52,000

กดบันทึก แล้วดูรายงานภาษี → ภาษีขายขึ้นเฉพาะส่วนที่รับเงินแล้ว และมีเลขใบกำกับภาษีที่ระบบออกให้

### ขั้นที่ 4 — ทดสอบว่าระบบกันข้อผิดพลาดจริงไหม (7 นาที)

นี่คือส่วนที่แยกระบบบัญชีจริงออกจากโปรแกรมทำเอกสารทั่วไป

| ลองทำ | ที่ไหน | ผลที่ควรได้ |
|---|---|---|
| **ลงบัญชีที่ Dr ≠ Cr** | ลงบัญชีมือ (ต้องใช้ `wipha` หรือ `malee`) | ปุ่มบันทึกกดไม่ได้ และถ้าข้ามไปได้ ฐานข้อมูลจะปฏิเสธพร้อมบอกผลต่าง |
| **ลงบัญชีย้อนเข้าเดือนกรกฎาคม** | ลงบัญชีมือ ใส่วันที่ 15/7/2569 | *"งวด 2026-07 สถานะ CLOSED : ห้ามบันทึกหรือแก้ไขรายการบัญชี"* |
| **แก้ไขรายการที่ลงบัญชีแล้ว** | สมุดรายวัน → เปิดใบใดก็ได้ | ไม่มีปุ่มแก้ไข มีแต่ "กลับรายการ" — ตามหลักการตรวจสอบย้อนกลับ |
| **รับชำระเกินยอดค้าง** | รับชำระเงิน ใส่ยอดเกิน | ระบบปฏิเสธพร้อมบอกยอดค้างจริง |

### ขั้นที่ 5 — ตรวจสิทธิ์ผู้ใช้ (5 นาที)

ออกจากระบบ แล้วเข้าใหม่ด้วย `owner` (ผู้บริหาร)

**สิ่งที่ควรเห็น:** เมนู "สร้างใหม่" หายไปทั้งหมด
ลองพิมพ์ URL ตรงไปที่ `http://localhost:3100/invoices/new` — ระบบจะแสดงหน้า "ไม่มีสิทธิ์เข้าถึง"
พร้อมบอกว่าบทบาทไหนทำได้บ้าง

ระบบบังคับสิทธิ์ **3 ชั้น**: ซ่อนเมนู · กันที่หน้าจอ · กันที่ตัวสั่งงานฝั่งเซิร์ฟเวอร์
การพิมพ์ URL ตรงหรือดัดแปลงคำสั่งจากเบราว์เซอร์จึงข้ามไม่ได้

### ขั้นที่ 6 — ดูรายงานและปิดงวด (5 นาที)

เข้าด้วย `malee` (ผู้จัดการบัญชี)

- **งบทดลอง** — ตรวจว่าเดบิตเท่ากับเครดิต และมียอดยกมาจากเดือนกรกฎาคม
- **งบแสดงฐานะการเงิน** — ตรวจว่ามีป้าย "สินทรัพย์ = หนี้สิน + ส่วนของผู้ถือหุ้น"
- **รายงานภาษี** — รูปแบบตามที่สรรพากรกำหนด มีเลขประจำตัวผู้เสียภาษีและรหัสสาขา
- **งวดบัญชี** — ลองกดปิดงวดสิงหาคม ระบบจะตรวจ 3 เงื่อนไขให้ก่อน และปฏิเสธถ้าไม่ผ่าน

| **e-Tax Invoice** | ไม่รวม | โครงสร้างเผื่อไว้แล้ว ยังไม่เชื่อมสรรพากร |

## 7. ก่อนนำไปใช้งานจริง ต้องทำอะไรบ้าง

ชุดนี้เป็น**ชุดสาธิต** ไม่ใช่ระบบพร้อมใช้งานจริง ต้องทำสิ่งเหล่านี้ก่อน

### จำเป็นต้องทำ

1. **ลบข้อมูลสาธิตออก** — แก้ `docker-compose.yml` ลบบรรทัด `05_demo_users` และ `06_sample_data`
   แล้วสร้างฐานข้อมูลใหม่ด้วย `docker compose down -v && docker compose up -d`
2. **ปิดโหมดสาธิต** — ตั้ง `DEMO_MODE: "false"` ใน `docker-compose.yml` เพื่อไม่ให้แสดงรายชื่อบัญชีในหน้าเข้าสู่ระบบ
3. **เปลี่ยนรหัสผ่านฐานข้อมูล** — `POSTGRES_PASSWORD` และ `DATABASE_URL` ในไฟล์เดียวกัน
4. **ให้บริการผ่าน HTTPS** — คุกกี้เซสชันจะตั้ง secure flag อัตโนมัติ ถ้าไม่มี HTTPS จะเข้าสู่ระบบไม่ได้
5. **สำรองข้อมูล** — พ.ร.บ.การบัญชี 2543 บังคับเก็บเอกสาร 5 ปี ต้องมีแผนสำรองและกู้คืน

### ต้องเตรียมข้อมูลก่อนเริ่มใช้

6. **ผังบัญชีจริงของกิจการ** — ผังที่ให้มาเป็นแบบมาตรฐานธุรกิจบริการ ต้องให้ผู้ทำบัญชีปรับให้ตรงกับกิจการ
7. **ให้ผู้ทำบัญชีหรือผู้สอบบัญชีตรวจกฎการลงบัญชี** ใน [posting-rules.md](posting-rules.md) ก่อนเริ่มใช้
   โดยเฉพาะอัตราภาษีหัก ณ ที่จ่ายรายประเภทเงินได้ และนโยบายค่าเสื่อมราคา
8. **ยอดยกมา** ณ วันที่จะเริ่มใช้ระบบ รวมถึงรายตัวลูกหนี้และเจ้าหนี้ที่ค้างชำระ
9. **ข้อมูลลูกค้าและผู้ขาย** พร้อมเลขประจำตัวผู้เสียภาษี 13 หลักและรหัสสาขา (จำเป็นสำหรับรายงานภาษี)

## 8. ติดปัญหา

| อาการ | สาเหตุที่พบบ่อย | วิธีแก้ |
|---|---|---|
| เปิด localhost:3100 ไม่ได้ | คอนเทนเนอร์ยังไม่พร้อม | `docker compose ps` ต้องขึ้น `healthy` ทั้งคู่ · ดู log ด้วย `docker compose logs web` |
| พอร์ต 3100 หรือ 5434 ชนกัน | มีโปรแกรมอื่นใช้อยู่ | แก้เลขพอร์ตซ้ายมือในส่วน `ports:` ของ `docker-compose.yml` |
| หน้าเว็บขึ้น "เชื่อมต่อฐานข้อมูลไม่ได้" | ฐานข้อมูลยังไม่พร้อม | รอสักครู่แล้วรีเฟรช · ถ้ายังไม่ได้ให้ `docker compose restart web` |
| อยากเริ่มใหม่หมด | — | `docker compose down -v` แล้ว `docker compose up -d --build` |
| ลืมรหัสผ่านที่ตั้งใหม่ | — | `docker compose down -v` เพื่อรีเซ็ตทั้งหมด (ข้อมูลหายทั้งหมด) |
