## 0. เริ่มเร็วที่สุด

ต้องมี Docker Desktop เปิดอยู่ ไม่ต้องติดตั้ง Node.js หรือ PostgreSQL

```bash
docker compose up -d --build
```

เปิด **http://localhost:3100** — ครั้งแรกระบบจะพาไปหน้าติดตั้ง ให้ตั้งข้อมูลกิจการและผู้ดูแลระบบคนแรก

ระบบมาแบบ**ว่างเปล่าพร้อมใช้งานจริง** มีแต่ผังบัญชีมาตรฐาน 79 บัญชี ไม่มีข้อมูลสมมติ
อ่าน [docs/production-checklist.md](docs/production-checklist.md) ก่อนกรอกข้อมูลบัญชีจริง

### อยากดูชุดสาธิตพร้อมข้อมูลตัวอย่าง

```bash
docker compose -f docker-compose.yml -f docker-compose.demo.yml up -d --build
```

ได้ข้อมูลบริษัทสมมติ 2 เดือน และผู้ใช้ทดลอง 5 บทบาท รหัสผ่าน `Demo@2569`

### ให้เครื่องอื่นเข้าถึง

```bash
.\share.ps1
```

แสดงลิงก์ทั้งหมดที่ใช้แชร์ได้ (localhost / วงแลน / Tailscale) และสถานะไฟร์วอลล์

## 2. ข้อมูลหลักที่ต้องกรอกก่อนออกเอกสาร

ทั้งหมดทำผ่านหน้าจอได้ ไม่ต้องแตะฐานข้อมูล — แดชบอร์ดจะขึ้นเช็กลิสต์บอกว่าเหลืออะไร

| ข้อมูล | เมนู | ใครทำได้ |
|---|---|---|
| ข้อมูลกิจการ ที่อยู่ เลขผู้เสียภาษี | ตั้งค่า → ตั้งค่ากิจการ | ผู้จัดการบัญชี |
| ปีบัญชีและงวดบัญชี | บัญชี → งวดบัญชี | ผู้จัดการบัญชี |
| ผังบัญชี (เพิ่ม/ปิดใช้งาน) | บัญชี → ผังบัญชี | ผู้จัดการบัญชี |
| บัญชีธนาคาร | ตั้งค่า → บัญชีธนาคาร | ผู้จัดการบัญชี |
| ศูนย์ต้นทุน | ตั้งค่า → ศูนย์ต้นทุน | ผู้จัดการบัญชี |
| ลูกค้าและผู้ขาย | ตั้งค่า → ลูกค้าและผู้ขาย | นักบัญชีขึ้นไป |
| ผู้ใช้งานและบทบาท | ตั้งค่า → ผู้ใช้งาน | ผู้จัดการบัญชี |
| การส่งข้อมูลให้นักบัญชี | ตั้งค่า → ส่งข้อมูลให้นักบัญชี | ผู้จัดการบัญชี |

**ยอดยกมาตั้งต้น** บันทึกผ่าน บัญชี → ลงบัญชีมือ เลือกประเภท "ยอดยกมา"
รายละเอียดอยู่ใน [docs/production-checklist.md](docs/production-checklist.md) ส่วนที่ 3

## 4. ดูรายงาน

เข้า psql ก่อน

```bash
docker compose exec db psql -U postgres -d accounting
```

จากนั้นสั่งได้เลย

| ต้องการดู | คำสั่ง |
|---|---|
| งบทดลองเดือนสิงหาคม (งวดที่ 8) | `SELECT * FROM acc.fn_trial_balance(8);` |
| บัญชีแยกประเภทรายบัญชี | `SELECT * FROM acc.v_gl_movements WHERE account_code='1100' ORDER BY entry_date;` |
| อายุลูกหนี้ | `SELECT * FROM acc.v_ar_aging;` |
| **ตรวจสมการบัญชี** (ต้องเป็น 0) | `SELECT * FROM acc.v_accounting_equation_check;` |
| **กระทบยอดบัญชีคุม** (ต้องเป็น 0) | `SELECT * FROM acc.v_control_reconciliation;` |
| รายงานภาษีขาย | `SELECT * FROM acc.vat_output_items ORDER BY period_id, seq_no;` |
| รายงานภาษีซื้อ | `SELECT * FROM acc.vat_input_items ORDER BY period_id, seq_no;` |
| หนังสือรับรองหัก ณ ที่จ่ายที่ออก | `SELECT * FROM acc.wht_certificates;` |
| ภาษีที่ถูกลูกค้าหักไว้ (เครดิต ภงด.50) | `SELECT * FROM acc.wht_received;` |
| ใครแก้อะไรเมื่อไหร่ | `SELECT * FROM acc.audit_log ORDER BY changed_at DESC LIMIT 20;` |

สองรายการที่เป็นตัวหนาคือเครื่องมือเตือนภัย ถ้าไม่เป็นศูนย์เมื่อไหร่แปลว่าระบบเริ่มเพี้ยน

## 5. ลองลงบัญชีเอง

ลงบัญชีผ่านฟังก์ชัน `acc.post_journal_entry()` เท่านั้น อย่า INSERT ตารางตรง ๆ
ฟังก์ชันนี้จัดการลำดับ DRAFT → ใส่บรรทัด → POSTED ให้เอง และตรวจสมดุลทันที

```sql
SELECT acc.post_journal_entry(
    'JV2026-00018',           -- เลขที่ใบสำคัญ (ห้ามซ้ำ)
    DATE '2026-08-31',        -- วันที่ (ระบบหางวดให้เอง)
    'MANUAL',                 -- ประเภทที่มา
    'ค่าไฟฟ้าเดือนสิงหาคม',
    '[{"code":"5130","dr":3500,"memo":"ค่าไฟฟ้า"},
      {"code":"1150","dr":245,"memo":"ภาษีซื้อ"},
      {"code":"1020","cr":3745}]'::jsonb,
    1,                        -- ผู้บันทึก
    2                         -- ผู้อนุมัติ (ต้องไม่ใช่คนเดียวกัน)
);
```

ลองใส่ตัวเลขให้ไม่สมดุลดู ระบบจะปฏิเสธพร้อมบอกผลต่าง

**ยกเลิกรายการที่ลงบัญชีไปแล้ว** — แก้ไม่ได้ ต้องกลับบัญชีเท่านั้น

```sql
SELECT acc.reverse_journal_entry(
    17,                       -- id ของใบที่ต้องการกลับ
    'JV2026-00019',           -- เลขที่ใบกลับบัญชี
    DATE '2026-08-31',
    1, 2,
    'บันทึกผิดบัญชี'
);
```

**ปิดงวด** — ระบบจะตรวจเช็กลิสต์ให้เองก่อนอนุญาต (ไม่มีใบร่างค้าง, สมการสมดุล, บัญชีคุมตรงกับบัญชีย่อย)

```sql
SELECT acc.close_period(8, 2);
```

## 7. โครงสร้างหน้าจอ (web/)

Next.js 15 App Router + node-postgres **ไม่ใช้ ORM** โดยตั้งใจ เพราะตรรกะบัญชีอยู่ในฐานข้อมูลแล้ว
(constraint trigger + `acc.post_journal_entry`) การเพิ่ม ORM จะกลายเป็นชั้นที่ต้องสู้กับ DOMAIN type
และ stored function มากกว่าช่วย

```
web/src/
  lib/db.ts        การเชื่อมต่อ + ทรานแซกชัน + บังคับให้ NUMERIC เป็น string ห้ามเป็น float
  lib/money.ts     คำนวณเงินเป็นสตางค์จำนวนเต็มทั้งหมด + จัดรูปแบบวันที่ พ.ศ.
  lib/posting.ts   หัวใจของแอป — implement docs/posting-rules.md (R-1, R-2, P-1, P-3, กลับรายการ, ปิดงวด)
  lib/queries.ts   คิวรีอ่านที่ใช้ร่วมกัน
  app/             18 หน้า
  components/      ฟอร์มเอกสารและตัวช่วย
```

**หลักที่ยึดในชั้นแอป**
- ทุกการลงบัญชีอยู่ในทรานแซกชันเดียว — บันทึกเอกสาร ลงบัญชี อัปเดตบัญชีย่อย และสร้างแถวรายงานภาษี สำเร็จหรือล้มเหลวพร้อมกัน
- คำนวณเงินเป็น**สตางค์จำนวนเต็ม**เสมอ ไม่ใช้ทศนิยมลอยตัวแม้แต่ที่เดียว
- ระบบเลือก**ผู้อนุมัติที่ไม่ใช่ผู้บันทึก**ให้อัตโนมัติ ตามกฎ maker-checker ที่ฐานข้อมูลบังคับ
- ข้อความผิดพลาดจาก trigger เป็นภาษาไทยอยู่แล้ว จึงส่งต่อให้ผู้ใช้เห็นตรง ๆ

### ระบบเข้าสู่ระบบและสิทธิ์

| ส่วน | รายละเอียด |
|---|---|
| **รหัสผ่าน** | แฮชด้วย scrypt (N=2¹⁵, r=8, p=1) เกลือสุ่มรายบัญชี · เทียบแบบ constant-time |
| **เซสชัน** | โทเคนสุ่ม 32 ไบต์ เก็บเฉพาะค่าแฮชในฐานข้อมูล · คุกกี้ httpOnly + sameSite lax + secure เมื่อ production · อายุ 7 วัน · ถอนสิทธิ์ได้ |
| **กันเดารหัสผ่าน** | ผิด 5 ครั้งล็อก 15 นาที · ข้อความผิดพลาดเหมือนกันทุกกรณีเพื่อไม่ให้เดาว่ามีชื่อผู้ใช้นี้จริงหรือไม่ |
| **บังคับเปลี่ยนรหัสผ่าน** | ครั้งแรกที่เข้าใช้งาน และเปลี่ยนรหัสผ่านแล้วจะถอนเซสชันเครื่องอื่นทั้งหมด |
| **บันทึกการเข้าใช้งาน** | ทุกครั้งทั้งสำเร็จและไม่สำเร็จ พร้อม IP และอุปกรณ์ ดูได้ที่หน้าบัญชีของฉัน |
| **บังคับสิทธิ์ 3 ชั้น** | ซ่อนเมนู → กันที่หน้าจอ (`can()`) → กันที่ server action (`requirePermission()`) ทั้ง 7 action |

บทบาทและสิทธิ์นิยามไว้ที่ [web/src/lib/roles.ts](web/src/lib/roles.ts) จุดเดียว ทั้งฝั่งเซิร์ฟเวอร์และไคลเอนต์ใช้ร่วมกัน

### ข้อจำกัดของหน้าจอรุ่นนี้

| เรื่อง | สถานะ |
|---|---|
| จัดการลูกค้า/ผู้ขาย/ธนาคาร/ผู้ใช้/งวดบัญชี | ยังต้องเพิ่มผ่าน SQL |

| พิมพ์เอกสาร PDF | ยังไม่มี (มี print stylesheet ให้สั่งพิมพ์จากเบราว์เซอร์ได้) |

## 8. สถานะปัจจุบันและขั้นถัดไป

**มีแล้ว** — ฐานข้อมูลที่บังคับความถูกต้องทางบัญชีได้เองในตัว (ทดสอบผ่าน 47/47) และหน้าจอใช้งาน 18 หน้า
ที่ครอบคลุมวงจรรายรับ-รายจ่ายเต็มรอบพร้อมรายงานหลัก

**ขั้นถัดไปตามลำดับความสำคัญ**
1. **แทนผังบัญชีตัวอย่างด้วยผังบัญชีจริงของกิจการ** และให้ผู้ทำบัญชีตรวจ [docs/posting-rules.md](docs/posting-rules.md)
2. **เตรียมยอดยกมา** ณ วันที่จะเริ่มใช้ระบบ รวมถึงรายตัวลูกหนี้/เจ้าหนี้ที่ค้างชำระ
3. หน้าจัดการข้อมูลหลัก (ลูกค้า ผู้ขาย ธนาคาร ผู้ใช้ งวดบัญชี)
4. ใบลดหนี้ · นำเข้ายอดเงินเดือน · ทะเบียนสินทรัพย์ · กระทบยอดธนาคาร
5. พิมพ์ใบแจ้งหนี้/ใบกำกับภาษี/50 ทวิ เป็น PDF
6. ให้บริการผ่าน HTTPS และวางแผนสำรองข้อมูล (บังคับก่อนใช้งานจริง — ดู [docs/demo-guide.md §7](docs/demo-guide.md))
